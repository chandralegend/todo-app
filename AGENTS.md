## Instructions
1. Also make commits periodically with clear title and description of what you have done. This will help you keep track of your progress and also help others understand what you have done. title should follow the format: `[tag]: short description` where tag is one of the following: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`.
2. Make less Documentation and more code. Documentation is important but it should not be the main focus. The main focus should be on writing code that works and is easy to understand. and git commit will provide a good way to keep track of your progress and also help others understand what you have done. If and only if you need to write documentation, write them inside the `.docs` folder and arrange them in a way to find them easier, and if they are temperary, put them in a `temp` folder inside the `.docs` folder.
3. Do not push code to remote without the user's permission. Always ask the user before pushing code to remote. This will help you avoid making mistakes and also help you keep track of your progress.
4. Update `.docs/PROGRESS.md` file with the current progress of the project. This will help you keep track of your progress and also help others understand what you have done. Initially based on the user instructions and `.docs/PLAN.md`, you will need to update the `PROGRESS.md` file with the following information:
- Phased Plan with Each Phase's Tasks
  - Description
  - Status (Not Started, In Progress, Completed)
  - Sub Tasks (use a checklist format)
  - Summary of what has been done so far and what is left to do.
  - Notes (if any)
- Future Plans
  - Description of what you plan to do in the future.
  - Timeline for when you plan to do it.
  - Any dependencies or requirements for completing the future plans.

> IMPORTANT: Before Moving to a new Task or Making a commit, make sure to run type checks, linting, and tests.
